Adoption fixes reported by the first platform apps. **Contains one breaking change** (a budget cap of
`0`); see "Upgrading from 0.4.0".

```bash
pip install nexus-agent-framework==0.5.0
```

## Changes

* **Breaking: a monthly AI budget cap of `0` now switches AI off.** `MonthlyBudget(cap_usd=0)` refuses
  every billed call with `AiSpendDisabled` (HTTP 429, error `ai_disabled`) without reading the ledger.
  `None` means no cap. A negative or non numeric cap raises `ValueError` when the budget is built.
  In 0.4.0 a cap of 0 or less meant unlimited.
* `parse_budget_cap(value)` reads a cap from configuration (empty, `none` or `unlimited` give `None`).
* **Sync budget API** for worker threads: `ensure_within_budget_sync`, `record_sync`, `summary_sync`;
  `SpendLedger.record_sync` and `month_total_sync` (in `InMemorySpendLedger` and in `SqlSpendLedger`
  over a sync `Engine`).
* **`NexusTelemetryMiddleware` is plain ASGI** (no longer `BaseHTTPMiddleware`): an app's 413 body
  size limit is no longer turned into a 400 or 500. Caller request ids must be a plain token of at
  most 128 characters.
* **`SecurityHeadersConfig.no_store_prefixes`** sends `Cache-Control: no-store` on matching paths for
  every status, unless the route set its own.
* `docs/ADOPTING.md`: flat error body (`message` next to `error`), `ai_disabled`, cap rules, sync API.

## Upgrading from 0.4.0

* Passed `cap_usd=0` to mean "no cap"? Pass `None`, or read the setting with `parse_budget_cap`.
* Frontends read the error text from the top level `message`, not `error.message`.
* Sync code can use the `*_sync` budget methods.

Full guide: [docs/ADOPTING.md](https://github.com/sabburi1994/nexus/blob/v0.5.0/docs/ADOPTING.md#upgrading-from-040).
